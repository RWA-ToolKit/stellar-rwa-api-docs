# Filtering and sorting assets

<LastReviewed date={metadata.lastReviewed} />

`GET /v1/assets` accepts the query parameters below. Every parameter is
optional; with none supplied the route returns the first page of all indexed
assets.

## Query parameters

| Parameter | Type | Allowed values | Default | Invalid value |
| --- | --- | --- | --- | --- |
| `asset_type` | string | Any asset class string, matched exactly (e.g. `real_estate`, `invoice`, `commodity`, `bond`). | none (all classes) | Never an error: a value that matches no asset returns `200` with `[]`. |
| `active` | boolean | `true`, `false` | none (active and inactive) | Anything else (e.g. `maybe`) returns `400` `invalid_parameter`. |
| `sort` | enum | `valuation` (USD valuation) | none (no server-side sort) | Any other field (e.g. `name`) returns `400` `invalid_parameter`. |
| `order` | enum | `asc`, `desc` | `desc` when `sort` is set | Any other value (e.g. `up`) returns `400` `invalid_parameter`. Sending `order` without `sort` also returns `400`. |
| `limit` | integer | `1`–`100` | `50` | Non-numeric (`abc`), negative (`-1`), zero (`0`) or out-of-range (`999999`) values return `400` `invalid_parameter`. They are rejected, not clamped. |
| `offset` | integer | `0` or greater | `0` | Non-numeric (`abc`) or negative (`-1`) values return `400` `invalid_parameter`. |
| `fields` | comma-separated list | Field names of the asset object (e.g. `id,symbol,valuation_usd`) | none (full objects) | A name that is not a field of the asset object returns `400` `invalid_parameter`, and `message` lists the available fields. Names are not checked when the result is empty, so that case still returns `200` with `[]`. |

Any parameter not in this table (for example `bogus=1` or `asset_id=1`) is
rejected with `400` `invalid_parameter`. Unknown parameters are never silently
ignored.

## Combining parameters

- `asset_type` and `active` can be used together. An asset must match every
  filter you supply.
- `order` only modifies `sort`. Use it as `sort=valuation&order=asc`, or leave
  it out to get the highest valuation first.
- `limit` and `offset` page through the filtered and sorted result.
- `fields` is applied last, after filtering, sorting and pagination, so it only
  trims each returned object. See [Field selection](#field-selection) below.

```bash
curl "$API_BASE_URL/v1/assets?asset_type=real_estate&sort=valuation&order=asc"
```

## Errors

Invalid or unknown parameters return `400` with the shared error body. The body
has exactly two keys, `error` and `message`:

```json
{
  "error": "invalid_parameter",
  "message": "..."
}
```

See [API · Error Bodies](/docs/api/errors) for the canonical error shape and the full list of error codes.

## Empty results

When no assets match the supplied filters, `GET /v1/assets` returns `200` with
an empty JSON array — never `null` and never an error:

```json
[]
```

```bash
curl "$API_BASE_URL/v1/assets?asset_type=real_estate&active=false"
# 200 OK
# []
```

Malformed or out-of-range parameters (for example a non-integer `limit`, an
unknown `sort` value, or `order` without `sort`) still return `400` with the
shared error body `{"error": "invalid_parameter", "message": "..."}` — an empty
result set is only returned for valid parameters that match nothing.

## Field selection

Combine `?fields=` with the filter and sort parameters to trim each item in the
response to just the fields you need. Filtering and sorting still apply to the
full record set before the projection is applied.

```bash
curl "$API_BASE_URL/v1/assets?asset_type=real_estate&sort=valuation&order=asc&fields=id,symbol,valuation_usd"
```

An unknown field name returns `400` with a body of the form:

```json
{"error": "invalid_parameter", "message": "unknown field ..."}
```

See [API · Field Selection](/docs/api/field-selection) for the full list of
selectable fields and projection rules.
