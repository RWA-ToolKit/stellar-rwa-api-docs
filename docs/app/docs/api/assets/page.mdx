<CalloutBox variant="tip" title="New to Stellar? Key terms">
- **Ledger** — a numbered block of transactions on the Stellar network. Ledger sequences increase over time and are used as a clock (e.g. "held for 100 ledgers").
- **Base units** — the smallest indivisible unit of a token. A token with `decimals = 2` stores `1000000` base units for `10,000.00` display tokens.
- **`i128`** — a 128-bit signed integer, the on-chain type used for token amounts. The API returns these as decimal strings so JavaScript clients don't lose precision.
- **Contract address** — the `C…` identifier of a deployed Soroban smart contract (e.g. `token_contract`, `compliance_contract`).
- **Account address** — the `G…` identifier of a Stellar account (e.g. `issuer`).
- **SEP-41** — the Stellar standard token interface; contracts implementing it work with standard wallets and tooling.
- **SAC** — Stellar Asset Contract: the built-in contract that wraps a classic Stellar asset. Asset tokens here are custom contracts, not SACs.
- **TTL / footprint** — Soroban storage has a time-to-live (TTL) and each transaction declares a footprint (the ledger entries it reads/writes). These are handled by the contract and SDKs; the REST API does not expose them.
- **Passphrase** — the network identifier string (e.g. `Test SDF Network ; September 2015`) that distinguishes Testnet from Mainnet. It is configured in your SDK/CLI, not sent to this API.
</CalloutBox>

## List assets

<ApiEndpoint method="GET" path="/assets" description="All tokenized assets with valuation, supply and holder counts." />

Returns an array of asset objects.

**Query parameters** (all optional)

| Name | Type | Notes |
|------|------|-------|
| `asset_type` | string | Filter by class: `real_estate`, `invoice`, `commodity` |
| `active` | boolean | Filter by active status |
| `fields` | string | Sparse fieldset: comma-separated list such as `id,name,active`. See [Field selection](/docs/api/field-selection). |
| `offset` | integer | Skip the first N matching assets. Default: `0`. |
| `limit` | integer | Page size. Default: `50`; maximum: `100`. |

Results are paginated to keep large collections bounded. Use `offset` and `limit` together to walk the list in chunks.

```bash
curl "$API_BASE_URL/v1/assets?asset_type=real_estate&active=true&offset=0&limit=50"
```

### Field selection

Use `fields` to request a sparse fieldset and shrink the response to just the
attributes you need. Field names are validated against the asset schema; an
unknown name is rejected with `400` (see [Errors](/docs/api/errors)):

```bash
curl "$API_BASE_URL/assets?fields=id,symbol,valuation_usd,active"
```

```json
[
  {
    "id": 1,
    "symbol": "MLOFT",
    "valuation_usd": 5000000.0,
    "active": true
  }
]
```

```json
{ "error": "invalid_parameter", "message": "unknown field `valuation`" }
```

Returned with status `400` when any requested field is not part of the asset
schema. See [Field selection](/docs/api/field-selection) for the full rules.

## Worked example

This example is verified against the current Testnet deployment. It walks
through listing assets, then fetching a single asset by id.


```json
    "name": "Manhattan Loft",
```

## Get an asset

<ApiEndpoint method="GET" path="/assets/:id" description="Full detail for a single asset by registry id." />

**Path parameters**

| Name | Type | Notes |
|------|------|-------|
| `id` | number | Registry id (e.g. `1`) |

**Example**

```bash
curl $API_BASE_URL/v1/assets/1
```

Returns a single asset object with the schema above.

You can also request a sparse fieldset with `?fields=`; for example:

```bash
curl "$API_BASE_URL/v1/assets/1?fields=id,name,active,indexed_at_ledger"
```

See [Field selection](/docs/api/field-selection) for the full syntax.

**Errors**

```json
{ "error": "not_found", "message": "no asset with id 999" }
```

Returned with status `404` when no asset has the given id. A non-numeric id
(`/assets/abc`) is rejected with status `400`:

```json
{ "error": "bad_request", "message": "invalid asset id" }
```

All error responses use the shared body shape `{"error": "<code>", "message": "<text>"}`.
See [API · Errors](/docs/api/errors) for the canonical shape and the full list of codes.

<CalloutBox variant="tip" title="Amount units and conversions">
Both `total_supply` and `valuation_cents` are 128-bit integers returned as strings to prevent rounding in JavaScript runtimes.

```typescript
// 1. Converting total_supply (base units to display tokens):
// Given total_supply = "1000000" and decimals = 2:
const rawSupply = BigInt(asset.total_supply);
const displaySupply = Number(rawSupply) / (10 ** asset.decimals);
// => 10,000.00 MLOFT

// 2. Converting valuation_cents (USD cents to USD dollars):
// Given valuation_cents = "500000000":
const rawCents = BigInt(asset.valuation_cents);
const displayUsd = Number(rawCents) / 100;
// => 5000000.00 ($5,000,000.00 USD)
```
</CalloutBox>

## Contract entry points

The asset-token contract exposes the following entry points. They are invoked
directly on-chain (via the Stellar CLI or an SDK) rather than through the REST
API; the API only reflects their resulting state (`total_supply`, `holders`,
`paused`, etc.).

### SEP-41 token interface

Asset tokens implement the [SEP-41](https://github.com/stellar/stellar-protocol/blob/master/ecosystem/sep-0041.md)
token interface, so standard tooling works out of the box:

| Entry point | Description |
|-------------|-------------|
| `allowance(from, spender)` | Remaining amount `spender` may transfer on behalf of `from` |
| `approve(from, spender, amount, expiration_ledger)` | Set an allowance with an expiration ledger |
| `balance(id)` | Balance of an address in base units |
| `transfer(from, to, amount)` | Move tokens between addresses |
| `transfer_from(spender, from, to, amount)` | Move tokens using an existing allowance |
| `burn(from, amount)` | Burn tokens from an address |
| `burn_from(spender, from, amount)` | Burn tokens using an existing allowance |
| `decimals()` | Token precision (matches the API `decimals` field) |
| `name()` | Token name (matches the API `name` field) |
| `symbol()` | Token symbol (matches the API `symbol` field) |
