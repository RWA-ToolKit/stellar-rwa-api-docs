# Dividends

<CalloutBox variant="note">
Replace <code>$API_BASE_URL</code> in examples with your configured API base URL (see <a href="/docs/api/overview">API Overview</a>).
</CalloutBox>

<ApiEndpoint method="GET" path="/assets/:id/dividends" description="Distribution history for an asset, newest ledger first." />

Returns every dividend distribution created for the asset's token, ordered by
creation ledger (newest first).

**Path parameters**

| Name | Type | Notes |
|------|------|-------|
| `id` | number | Registry id |

**Response schema** (per distribution):

| Field | Type | Notes |
|-------|------|-------|
| `id` | number | Distribution id |
| `asset_token` | string | The asset paid out on |
| `payment_token` | string | Token used to pay |
| `total_amount` | string | Pool size, base units (`i128`) |
| `distributed` | string | Claimed so far, base units (`i128`) |
| `claimed_percent` | number | 0–100 (2 dp), unless `overflow_detected` is `true` |
| `completed` | boolean | `true` once fully claimed |
| `created_at_ledger` | number | |
| `overflow_detected` | boolean | On-chain anomaly indicator (see below) |

**Example**

```bash
curl $API_BASE_URL/assets/1/dividends
```

```json
[
  {
    "id": 1,
    "asset_token": "CBMCWLSQSWUTLUJFCNBHNBSXMUM3XU7NAQ5TSNERW4HA4ZZBYHLG4ECZ",
    "payment_token": "CDLZFC3SYJYDZT7K67VZ75HPJVIEUVNIXF47ZG2FB2RMQQVU2HHGCYSC",
    "total_amount": "100000000000",
    "distributed": "25000000000",
    "claimed_percent": 25.0,
    "completed": false,
    "created_at_ledger": 3510000
  }
]
```

An asset with no distributions returns an empty array `[]`.

### Understanding `overflow_detected`

The `overflow_detected` field signals an **on-chain anomaly**, not an API bug.

Under normal conditions, `distributed ≤ total_amount` and `claimed_percent` stays in
the range 0–100. If `overflow_detected` is `true`, it means `distributed` exceeds
`total_amount` — the pool has been over-claimed.

This can occur if the on-chain dividend contract has a double-claim vector (a
vulnerability in the contract logic that allows an account to claim multiple times).
It is **not** an API indexing error; the API is faithfully reflecting what the
blockchain shows.

**What integrators should do:**

- When `overflow_detected` is `true`, treat it as a **data integrity warning**.
- Check `claimed_percent` directly (it will exceed 100) rather than clamping it.
- Contact the asset issuer to investigate and remediate the underlying contract issue.
- The anomaly is immutable on-chain; responses will continue showing `overflow_detected: true`
  until the contract is fixed or migrated.

**Errors**

Returns `404` with `{ "error": "not_found", … }` when the asset id is unknown.

## Get a single distribution

<ApiEndpoint method="GET" path="/assets/:id/distributions/:did" description="A single distribution for an asset, by distribution id." />

**Path parameters**

| Name | Type | Notes |
|------|------|-------|
| `id` | number | Registry id |
| `did` | number | Distribution id |

**Response schema**

Same shape as a single item from the list above.

**Example**

```bash
curl $API_BASE_URL/assets/1/distributions/1
```

```json
{
  "id": 1,
  "asset_token": "CBMCWLSQSWUTLUJFCNBHNBSXMUM3XU7NAQ5TSNERW4HA4ZZBYHLG4ECZ",
  "payment_token": "CDLZFC3SYJYDZT7K67VZ75HPJVIEUVNIXF47ZG2FB2RMQQVU2HHGCYSC",
  "total_amount": "100000000000",
  "distributed": "25000000000",
  "claimed_percent": 25.0,
  "completed": false,
  "created_at_ledger": 3510000
}
```

**Errors**

Returns `404` with `{ "error": "not_found", … }` when the asset id or the distribution id is unknown.

<CalloutBox variant="note">
`total_amount` and `distributed` are in the **payment token's** base units, not the
asset token's. Classic Stellar assets (SACs) use 7 decimals, so `100000000000`
above is `10,000.0` units of the payment token.
</CalloutBox>
