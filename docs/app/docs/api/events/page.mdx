# Events

<LastReviewed date={metadata.lastReviewed} />

The API exposes a compact event stream for clients that need to react to state changes without polling the full asset list. The payload is a JSON array ordered newest-first.

<ApiEndpoint method="GET" path="/v1/events" description="Most recent contract events captured by the indexer.">

```bash
curl "$API_BASE_URL/v1/events?limit=20"
```

```json
[
  {
    "id": 42,
    "contract": "CDL...",
    "event_type": "Transfer",
    "ledger": 3514152,
    "timestamp": "2026-07-09T08:43:12.101772791+00:00",
    "data": {
      "from": "GA...",
      "to": "GB...",
      "amount": "100"
    }
  }
]
```

**Field selection:**

Use the `fields` query parameter to return only the event fields you need. See [Field Selection](/docs/api/field-selection) for the full syntax.

```bash
curl "$API_BASE_URL/v1/events?limit=20&fields=id,event_type,ledger"
```

```json
[
  {
    "id": 42,
    "event_type": "Transfer",
    "ledger": 3514152
  }
]
```

Requesting a field that does not exist on `Event` returns a `400` error with code `invalid_parameter`:

```json
{
  "error": "invalid_parameter",
  "message": "Unknown field: 'foo'"
}
```

</ApiEndpoint>

**Response schema** (`Event`, per event):

| Field | Type | Unit | Nullable | Description |
|-------|------|------|----------|-------------|
| `id` | integer | Event id | No | Indexer-assigned event id |
| `contract` | string | — | No | Contract address that emitted the event |
| `event_type` | string | — | No | Event name |
| `ledger` | integer | Ledger sequence | No | Ledger containing the event |
| `timestamp` | string | RFC 3339 timestamp | Yes | JSON `null` when the ledger timestamp is unavailable |
| `data` | JSON value | — | No | Raw event payload |

Each event includes the contract address, event name, ledger, timestamp (when available), and the raw payload emitted by the contract.

**Pagination:**

The events endpoint is cursor-paginated. Pass `limit` (default `20`, max `100`) to bound the page size and `cursor` to fetch the next page. The response is a JSON array; when more events are available the `Link` header carries a `rel="next"` URL whose `cursor` query parameter can be replayed verbatim. See [Pagination](/docs/api/pagination) for the shared cursor conventions used across endpoints.

```bash
# First page
curl -i "$API_BASE_URL/v1/events?limit=20"
# Follow the Link: <...?cursor=...>; rel="next" header for the next page
curl "$API_BASE_URL/v1/events?limit=20&cursor=$CURSOR"
```

## Worked example

The following script fetches the latest events from the current Testnet deployment and prints a compact summary. It follows the `Link` header to page through results and converts `Transfer` amounts using the token's decimals.

```bash
# Set the base URL for the current Testnet deployment
export API_BASE_URL="https://api.testnet.example.com"

# Fetch the first page of events
curl -s "$API_BASE_URL/v1/events?limit=5" | jq .
```

```typescript
const API_BASE_URL = process.env.API_BASE_URL ?? "https://api.testnet.example.com";

async function fetchEvents(limit = 20) {
  const res = await fetch(`${API_BASE_URL}/v1/events?limit=${limit}`);
  if (!res.ok) {
    throw new Error(`Events request failed: ${res.status} ${res.statusText}`);
  }
  const events = await res.json();
  const next = res.headers.get("link");
  return { events, next };
}

const { events, next } = await fetchEvents(5);
for (const event of events) {
  console.log(`#${event.id} ${event.event_type} @ ledger ${event.ledger}`);
}
if (next) {
  console.log(`Next page: ${next}`);
}
```

<CalloutBox variant="tip" title="Verify against Testnet">
Run the snippet above with `API_BASE_URL` pointed at the current Testnet deployment. A successful response returns a JSON array of events (possibly empty on a fresh deployment) and, when more pages exist, a `Link` header with `rel="next"`.
</CalloutBox>

**Event payload amount units:**

Amounts inside `data` depend on the contract and event type, in accordance with the [contracts specification](/docs/contracts/asset-token):

| Event type | Amount field | Unit / Base | Conversion |
|---|---|---|---|
| `Transfer`, `Mint`, `Burn` | `data.amount` | Asset token base units (`i128` string) | `Number(BigInt(data.amount)) / 10 ** token.decimals` |
| `Valuation` | `data.new_valuation` | USD cents (`i128` string) | `Number(BigInt(data.new_valuation)) / 100` |
| Dividend `created` | `data.total_amount` | Payment token base units (`i128` string) | `Number(BigInt(data.total_amount)) / 10 ** payment_token.decimals` |
| Dividend `claim` | `data.amount` | Payment token base units (`i128` string) | `Number(BigInt(data.amount)) / 10 ** payment_token.decimals` |

<CalloutBox variant="tip" title="Event amount conversion example">
```typescript
// For a Transfer event with amount = "100" and token decimals = 2:
const rawAmount = BigInt(event.data.amount);
const displayAmount = Number(rawAmount) / (10 ** 2);
// => 1.00 token
```
</CalloutBox>

## Errors

Every error response uses the shared two-field body shape:

```json
{
  "error": "invalid_limit",
  "message": "limit must be between 1 and 100"
}
```

| Field | Type | Description |
|-------|------|-------------|
| `error` | string | Stable, machine-readable error code |
| `message` | string | Human-readable description of the problem |

See [Errors](/docs/api/errors) for the canonical error shape, the full list of codes, and the HTTP status codes each one maps to.

**Event types by entry point:**

The indexer records one event per state-changing contract entry point. The table below maps the current contract surface to the `event_type` values you will see on this endpoint. See the [Asset Token Contract](/docs/contracts/asset-token) and [Dividends](/docs/contracts/dividends) references for the full entry-point definitions.

| Entry point | `event_type` | Notes |
|---|---|---|
| `transfer`, `transfer_from` | `Transfer` | SEP-41 token transfer; `data.amount` in asset base units |
| `mint` | `Mint` | SEP-41 issuance; `data.amount` in asset base units |
| `burn`, `burn_from` | `Burn` | SEP-41 redemption; `data.amount` in asset base units |
| `approve`, `allowance` | `Approve` | SEP-41 allowance update; `data.amount` in asset base units |
| `batch_transfer`, `batch_mint`, `batch_burn` | `Transfer`, `Mint`, `Burn` | One event per item in the batch, sharing the same `ledger` |
| `set_valuation` | `Valuation` | `data.new_valuation` in USD cents |
| `set_min_holding_period` | `MinHoldingPeriodUpdated` | `data.min_holding_period` in seconds |
| `transfer_admin`, `accept_admin`, `renounce_admin` | `AdminTransferInitiated`, `AdminTransferred`, `AdminRenounced` | Two-step admin handover |
| `create_dividend` | `created` | `data.total_amount` in payment token base units |
| `claim_dividend` | `claim` | `data.amount` in payment token base units |
| `set_dividend_deadline` | `DividendDeadlineUpdated` | `data.deadline` is a ledger sequence |
| `reclaim_dividend` | `DividendReclaimed` | `data.amount` in payment token base units |
| `cancel_dividend` | `DividendCancelled` | `data.dividend_id` identifies the cancelled dividend |

<CalloutBox variant="note" title="Batch operations">
Batch entry points emit one event per item rather than a single aggregate event. Filter by `event_type` and group by `ledger` to reconstruct a batch.
</CalloutBox>

## Glossary

New to Stellar or this API? These terms appear throughout the page:

- **Ledger sequence** — a monotonically increasing integer identifying a ledger (a batch of transactions) on the Stellar network. Higher numbers are more recent. See [Time & Ledgers](/docs/time-and-ledgers).
- **RFC 3339 timestamp** — the standard date/time string format used for `timestamp`, e.g. `2026-07-09T08:43:12.101772791+00:00`.
- **`i128`** — a 128-bit signed integer. Soroban contracts encode large amounts as `i128`; the API serializes them as decimal strings so no precision is lost in JSON.
- **Base units** — the smallest indivisible unit of a token. Divide by `10 ** decimals` to get the human-readable amount (e.g. a token with 2 decimals stores `100` base units as `1.00`).
- **SEP-41** — the Stellar token interface standard that defines `transfer`, `mint`, `burn`, and `approve` entry points.
- **Entry point** — a callable contract function. Each state-changing entry point emits one event.
- **Cursor** — an opaque pagination token returned in the `Link` header; replay it verbatim to fetch the next page. See [Pagination](/docs/api/pagination).
