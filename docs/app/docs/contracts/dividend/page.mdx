# Dividend Contract

<LastReviewed date={metadata.lastReviewed} />

Distributes yield/dividends to asset-token holders in proportion to their
holdings. An issuer funds a distribution with a payment token; each holder then
claims `total_amount * balance / total_supply`, paid from the escrow this contract
holds. Each holder can claim a given distribution once.

Balances are read **at claim time** from the asset token.

A distribution may carry an optional **claim deadline**. When a deadline is set,
claims after it revert with `DeadlinePassed (8)`; the admin can then `reclaim` the
unclaimed remainder, or `cancel` the distribution entirely before any claims are
made. Distributions created without a deadline remain claimable indefinitely.

**Testnet:** `CAR4XY3CEBQWFOL27JEWFW34KXSIZA7RFKDQMEIV7ZU723RWY37I2SYX`

## Data types

`Distribution`:

| Field | Type | Notes |
|-------|------|-------|
| `id` | `u64` | Assigned sequentially |
| `asset_token` | `Address` | The asset being paid out on |
| `payment_token` | `Address` | The token used to pay (e.g. USDC) |
| `total_amount` | `i128` | Pool size in payment-token base units |
| `distributed` | `i128` | Claimed so far |
| `created_at` | `u32` | Ledger at creation |
| `deadline` | `Option<u32>` | Optional claim deadline ledger; `None` = no deadline |
| `cancelled` | `bool` | `true` once the admin cancels the distribution |
| `completed` | `bool` | `true` once fully claimed, reclaimed, or cancelled |

## Function reference

### `initialize`

```rust
fn initialize(env: Env, admin: Address)
```

Sets the admin. Callable once. **Auth:** `admin`. Errors: `AlreadyInitialized (1)`.

### `set_admin`

```rust
fn set_admin(env: Env, admin: Address, new_admin: Address)
```

Hands admin control over to `new_admin`. **Auth:** current `admin`. Errors:
`Unauthorized (3)` if the caller is not the stored admin.

### `set_min_holding_period`

```rust
fn set_min_holding_period(env: Env, admin: Address, seconds: u32)
```

Sets the minimum holding period (in seconds) a holder must have held the asset
before claiming. **Auth:** `admin`. Errors: `Unauthorized (3)`.

### `create_distribution`

```rust
fn create_distribution(
    env: Env, admin: Address, asset_token: Address,
    payment_token: Address, total_amount: i128,
    deadline: Option<u32>,
) -> u64
```

Creates and funds a distribution, pulling `total_amount` of `payment_token` from
the admin into the contract's escrow. Returns the distribution id. Pass `None`
for `deadline` to leave the distribution claimable indefinitely.

- **Auth:** `admin` (must equal the stored admin; the transfer also requires the admin's authorization)
- **Errors:** `Unauthorized (3)`, `InvalidAmount (5)` if `total_amount <= 0`.

<CalloutBox variant="warning">
The admin must hold at least `total_amount` of the payment token and the transfer
must succeed, or `create_distribution` reverts. Funds are escrowed in the dividend
contract until claimed, reclaimed, or cancelled.
</CalloutBox>

### `create_distributions_batch`

```rust
fn create_distributions_batch(
    env: Env, admin: Address, asset_token: Address,
    payment_token: Address, total_amounts: Vec<i128>,
    deadlines: Vec<Option<u32>>,
) -> Vec<u64>
```

Creates several distributions for the same asset/payment token in one call.
`total_amounts` and `deadlines` must have equal length. Returns the new ids in
order. **Auth:** `admin`. Errors: `Unauthorized (3)`, `InvalidAmount (5)`,
`LengthMismatch (9)` if the vectors differ in length.

### `claimable`

```rust
fn claimable(env: Env, distribution_id: u64, holder: Address) -> i128
```

Returns the amount a holder can still claim: `0` if already claimed, if they hold
nothing, if the distribution is empty, cancelled, past its deadline, or the holder
has not met the minimum holding period. Otherwise
`total_amount * balance / total_supply` (floored by integer division), where
`balance` and `total_supply` are read from the asset token at the time of the
call. This is a view function: no authorization is required and it has no
state change. **Errors:** `DistributionNotFound (4)` for an unknown id.

### `claim`

```rust
fn claim(env: Env, distribution_id: u64, holder: Address)
```

Pays the holder's proportional share from escrow and marks it claimed.

- **Auth:** `holder`
- **Errors:** `DistributionNotFound (4)`, `AlreadyClaimed (7)`, `NothingToClaim (6)`,
  `DeadlinePassed (8)` if the deadline has elapsed, `HoldingPeriodNotMet (10)` if
  the holder has not held the asset for the configured minimum period.

### `reclaim`

```rust
fn reclaim(env: Env, admin: Address, distribution_id: u64) -> i128
```

After the deadline has passed, returns the unclaimed remainder to the admin and
marks the distribution `completed`. Returns the reclaimed amount. **Auth:**
`admin`. Errors: `Unauthorized (3)`, `DistributionNotFound (4)`,
`DeadlineNotPassed (11)` if the deadline has not yet elapsed.

### `cancel`

```rust
fn cancel(env: Env, admin: Address, distribution_id: u64)
```

Cancels a distribution before any claims are made, returning the full escrow to
the admin. **Auth:** `admin`. Errors: `Unauthorized (3)`, `DistributionNotFound (4)`,
`AlreadyClaimed (7)` if any holder has already claimed.

### `get_distribution` / `get_distributions_for_asset` / `has_claimed`

```rust
fn get_distribution(env: Env, distribution_id: u64) -> Distribution
fn get_distributions_for_asset(env: Env, asset_token: Address, offset: u32, limit: u32) -> Vec<Distribution>
fn has_claimed(env: Env, distribution_id: u64, holder: Address) -> bool
```

View helpers. `get_distributions_for_asset` is paginated via `offset`/`limit`
and backs the API's `/assets/:id/dividends` endpoint. None requires
authorization. `get_distribution` reports `DistributionNotFound (4)` for an
unknown id; `has_claimed` returns `false` when the holder has not claimed, and
`get_distributions_for_asset` returns an empty list when the asset has no
distributions or the offset is past the end.

## Code example

```ts
const dividend = new Contract("CAR4XY3C…2SYX");
// issuer funds a 10,000-unit distribution in the payment token, claimable for 30 days
const create = dividend.call(
  "create_distribution",
  new Address(admin).toScVal(),
  new Address(assetToken).toScVal(),
  new Address(paymentToken).toScVal(),
  nativeToScVal(10_000_0000000n, { type: "i128" }), // 10,000 @ 7 decimals
  nativeToScVal(deadlineLedger, { type: "u32" }), // or xdr.ScVal.scvVoid() for no deadline
);

// a holder later claims their share
const claim = dividend.call(
  "claim",
  nativeToScVal(1n, { type: "u64" }),
  new Address(holder).toScVal(),
);
```

## Security considerations

- **Balances are read at claim time**, not at snapshot. A holder who acquires more
  tokens after a distribution is created — but before claiming — claims on the
  larger balance. Issuers should be aware of this when timing distributions, or
  pause the token around distribution windows.
- **Integer division floors** each share, so a tiny residual may remain in escrow
  after everyone claims; `completed` flips once `distributed >= total_amount`.
- **Escrow custody:** funds live in the dividend contract between creation and
  claim. The contract only pays out via `claim`, or returns funds to the admin via
  `reclaim` (after the deadline) or `cancel` (before any claims).
- **Payment-token decimals differ** from the asset token. Amounts here are in the
  payment token's base units (7 for classic Stellar assets / SACs — Stellar Asset
  Contracts, the Soroban-compatible wrappers for classic Stellar assets like USDC).
