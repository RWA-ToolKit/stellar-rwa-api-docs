# Registry Contract

The registry is the on-chain source of truth for which assets exist. It maps
asset ids to their token contracts and metadata, and is the entry point every
indexer uses to discover assets.

## Asset discovery mechanism

The registry does **not** emit events that indexers subscribe to, and it does
not push updates. Asset discovery is **polling-based**: an indexer repeatedly
calls the registry's view functions to enumerate the current set of assets.

### Discovery calls

Discovery is driven by two read-only view functions:

- `get_asset_count() -> u32` — the total number of registered assets.
- `get_all_assets(start_id: u32, limit: u32) -> Vec<AssetEntry>` — a paginated
  slice of the registry, ordered by asset id.

An indexer discovers assets by paging through `get_all_assets` from
`start_id = 0` in fixed-size pages until it has read `get_asset_count()`
entries. The reference indexer uses a page size of 50
(`REGISTRY_PAGE_SIZE`). Each page is a pure `simulateTransaction` view call —
no transaction is submitted and no signing key is required.

### Timing relative to the 10s poll interval

Discovery runs as part of the indexer's refresh cycle, which fires every
**10 seconds** (`POLL_INTERVAL`). On each cycle the indexer:

1. Reads `get_asset_count()` to learn the current asset total.
2. Pages through `get_all_assets` to enumerate every asset id.
3. For each discovered asset, reads the asset-token and compliance contracts
   to build the per-asset snapshot.

Because discovery is polled rather than event-driven, a newly registered
asset becomes visible to the API at most one poll interval (10 s) after the
registration transaction is finalized on-chain. There is no push
notification and no event subscription to configure.

### Failure handling

Individual reads retry transient RPC failures in place with jittered
backoff (base 150 ms, capped at 2 s, up to 4 attempts) — deliberately much
shorter than the 10 s poll interval so a transient error does not abort the
whole cycle. If a refresh cycle still fails, the indexer logs the error and
waits for the next poll interval rather than panicking, so the API keeps
serving the last good snapshot.

### Building your own indexer

If you are writing your own indexer against the registry:

- Poll `get_asset_count()` + `get_all_assets(start_id, limit)` on your own
  cadence; 10 s matches the reference indexer and bounds discovery lag.
- Treat the registry as append-only for discovery purposes: page from
  `start_id = 0` and stop once you have read `get_asset_count()` entries.
- Do not rely on events for discovery — none are emitted for registration.
- Use `simulateTransaction` for reads; no key or submitted transaction is
  needed.
