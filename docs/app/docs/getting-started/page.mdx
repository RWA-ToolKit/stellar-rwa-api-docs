# Getting Started

The **Stellar RWA Toolkit** is an end-to-end system for tokenizing real-world
assets (RWAs) — real estate, invoices, commodities — on Stellar using Soroban
smart contracts, with **compliance enforced on-chain**.

It has three parts, each in its own repository:

- **Contracts** — four Soroban contracts: `asset-token`, `compliance`, `registry`, `dividend`.
- **API** — a Rust/Axum service that indexes all tokenized-asset activity and serves it over REST.
- **Web app** — a Next.js front-end for issuers and investors.

## What "tokenizing a real-world asset" means

A real-world asset — say a $5,000,000 Manhattan loft — is represented on-chain as
a fungible token. Each token is a fractional claim on the underlying asset. Unlike
an ordinary token, an RWA token is **compliance-gated**: only addresses that have
passed KYC and sit on an allowlist may hold or receive it.

The gate is not a policy sitting in a database — it is enforced by the contract
itself. On every transfer, the asset-token contract makes a cross-contract call
into the compliance contract to check both the sender and the recipient. If either
fails, the transfer reverts.

<CalloutBox variant="compliance" title="Why this matters">
Securities laws in most jurisdictions restrict who may hold a regulated asset.
Enforcing that restriction **in the contract** — rather than in an app that can be
bypassed — is what makes a token suitable to represent a regulated real-world
asset. See the [Compliance Guide](/docs/compliance-guide).
</CalloutBox>

## How the pieces fit together

```
                         ┌───────────────┐
   issuer / investor ──▶ │  Web app      │ ──▶ Freighter ──▶ Soroban contracts
                         └───────────────┘                       │
                                                                 │ events + state
                         ┌───────────────┐   polls Soroban RPC   │
   analysts / bots  ──▶  │  REST API     │ ◀─────────────────────┘
                         └───────────────┘
```

- The **web app** signs and submits transactions through the user's wallet.
- The **API** only reads: it indexes on-chain state every 10 seconds and never
  holds a key or signs anything.

## Prerequisites

- [Freighter](https://freighter.app) browser extension (for the web app)
- Node.js 18+ (web app and docs)
- Rust 1.75+ (API and contracts)
- The [Stellar CLI](https://developers.stellar.org/docs/tools/cli) (to deploy contracts)

## Quickstart

Run the API against the deployed Testnet contracts:

```bash
git clone https://github.com/your-org/stellar-rwa-api-docs
cd stellar-rwa-api-docs/api
cp .env.example .env      # Testnet defaults are pre-filled
cargo run
# → listening on 0.0.0.0:8080
```

Then query it:

```bash
curl http://localhost:8080/stats
curl http://localhost:8080/assets
```

Run the docs site:

```bash
cd ../docs
npm install
npm run dev               # http://localhost:3000
```

## Troubleshooting

### `cargo build` fails while compiling `aws-lc-sys`

The API's TLS stack (`reqwest` with `rustls-tls`, pulled in transitively via
`stellar-xdr`/`stellar-strkey`'s dependency tree) resolves to `aws-lc-rs` /
`aws-lc-sys` on most platforms. `aws-lc-sys` compiles a vendored C/assembly
library as part of the build, which is the most common source of build
friction for new contributors running `cargo run` or `cargo build` in `api/`
for the first time — even though `api/` is maintainer-owned for PRs,
contributors still need it running locally to verify doc examples against a
real response.

Typical failure signature:

```
error: failed to run custom build command for `aws-lc-sys v...`
...
CMake Error: CMake was unable to find a build program
```

or, on a successful CMake step but a missing C toolchain:

```
cc: command not found
```

**Fix — install the build prerequisites before `cargo build`:**

- **cmake** (required — `aws-lc-sys` builds via CMake)
- **A C/C++ compiler** — `clang` is preferred and tested upstream; `gcc` also
  works
- **Go 1.18+** (only needed if CMake falls back to the Go-based assembly
  perl-less path on your platform — usually not required if `perl` is
  present)
- **perl** (used to process `aws-lc`'s assembly sources on most platforms;
  typically already present on Linux/macOS)

Install commands by platform:

```bash
# Debian/Ubuntu
sudo apt-get install -y cmake clang

# Fedora
sudo dnf install -y cmake clang

# macOS (Homebrew)
brew install cmake llvm

# Windows
# Use a recent Visual Studio Build Tools install (C++ workload) plus
# cmake from https://cmake.org/download/, or build inside WSL2 instead.
```

<CalloutBox variant="note">
If you only need to read or edit the docs site or contracts, you can skip
this entirely — `npm run dev` in `docs/` and `stellar contract build` in the
contract crates don't touch `aws-lc-sys`. It's only required for building or
running `api/`.
</CalloutBox>

After installing, re-run `cargo build` (or `cargo run`) from `api/`; the
`aws-lc-sys` build step should complete without re-running `cmake`/`cc`
lookups on subsequent builds since Cargo caches the compiled artifact.

Continue to the [Compliance Guide](/docs/compliance-guide) — the concept that
makes this an RWA platform rather than a plain token factory.
