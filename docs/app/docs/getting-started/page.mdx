# Getting Started

The **Stellar RWA Toolkit** is an end-to-end system for tokenizing real-world
assets (RWAs) — real estate, invoices, commodities — on Stellar using Soroban
smart contracts, with **compliance enforced on-chain**.

It has three parts, each in its own repository:

- **Contracts** — four Soroban contracts: `asset-token`, `compliance`, `registry`, `dividend`.
- **API** — a Rust/Axum service that indexes all tokenized-asset activity and serves it over REST.
- **Web app** — a Next.js front-end for issuers and investors.

## What "tokenizing a real-world asset" means

A real-world asset — say a $5,000,000 Manhattan loft — is represented on-chain as
a fungible token. Each token is a fractional claim on the underlying asset. Unlike
an ordinary token, an RWA token is **compliance-gated**: only addresses that have
passed KYC and sit on an allowlist may hold or receive it.

The gate is not a policy sitting in a database — it is enforced by the contract
itself. On every transfer, the asset-token contract makes a cross-contract call
into the compliance contract to check both the sender and the recipient. If either
fails, the transfer reverts.

<CalloutBox variant="compliance" title="Why this matters">
Securities laws in most jurisdictions restrict who may hold a regulated asset.
Enforcing that restriction **in the contract** — rather than in an app that can be
bypassed — is what makes a token suitable to represent a regulated real-world
asset. See the [Compliance Guide](/docs/compliance-guide).
</CalloutBox>

## How the pieces fit together

```
                         ┌───────────────┐
   issuer / investor ──▶ │  Web app      │ ──▶ Freighter ──▶ Soroban contracts
                         └───────────────┘                       │
                                                                 │ events + state
                         ┌───────────────┐   polls Soroban RPC   │
   analysts / bots  ──▶  │  REST API     │ ◀─────────────────────┘
                         └───────────────┘
```

- The **web app** signs and submits transactions through the user's wallet.
- The **API** only reads: it indexes on-chain state every 10 seconds and never
  holds a key or signs anything.

## Prerequisites

- [Freighter](https://freighter.app) browser extension (for the web app)
- Node.js 18+ (web app and docs)
- Rust 1.75+ (API and contracts)
- The [Stellar CLI](https://developers.stellar.org/docs/tools/cli) (to deploy contracts)

## Quickstart

### Running the API locally

Run the API against the deployed Testnet contracts:

```bash
git clone https://github.com/your-org/stellar-rwa-api-docs
cd stellar-rwa-api-docs/api
cp .env.example .env      # Testnet defaults are pre-filled
cargo run
# → listening on 0.0.0.0:8080
```

### Environment variables

The API reads the following environment variables:

| Variable | Default | Description |
|----------|---------|-------------|
| `RWA_RPC_URL` | `https://soroban-testnet.stellar.org` | Soroban RPC endpoint the indexer polls |
| `RWA_REGISTRY_ID` | `CBX5SMLTXX6JP4HA5GQIO2V6QM7WCUGL2GZ6D4U773HMRI6RXISKPUR3` | Deployed registry contract id (Testnet) |
| `RWA_DIVIDEND_ID` | `CAR4XY3CEBQWFOL27JEWFW34KXSIZA7RFKDQMEIV7ZU723RWY37I2SYX` | Deployed dividend contract id (Testnet) |
| `RWA_READ_SOURCE` | `GAIQGTOBTTLLDJ4SWGGESM7UWJ2DI4K3ZNHUSHPDKJL2IE5FKY3BSRAA` | Funded account used as source for read simulations (must exist on the RPC) |
| `PORT` | `8080` | HTTP server port |
| `RUST_LOG` | `stellar_rwa_api=info,tower_http=warn` | Log filter (tracing-subscriber format) |

The `.env.example` file includes Testnet defaults. Copy it and adjust as needed for your network.

### Running with Docker

Build and run the API in a container:

```bash
cd stellar-rwa-api-docs/api
docker build -t stellar-rwa-api .
docker run -p 8080:8080 \
  -e RWA_RPC_URL=https://soroban-testnet.stellar.org \
  -e RWA_REGISTRY_ID=CBX5SMLTXX6JP4HA5GQIO2V6QM7WCUGL2GZ6D4U773HMRI6RXISKPUR3 \
  -e RWA_DIVIDEND_ID=CAR4XY3CEBQWFOL27JEWFW34KXSIZA7RFKDQMEIV7ZU723RWY37I2SYX \
  -e RWA_READ_SOURCE=GAIQGTOBTTLLDJ4SWGGESM7UWJ2DI4K3ZNHUSHPDKJL2IE5FKY3BSRAA \
  -e PORT=8080 \
  stellar-rwa-api
```

Or use an `.env` file:

```bash
docker run -p 8080:8080 --env-file .env stellar-rwa-api
```

Then query it:

```bash
curl http://localhost:8080/stats
curl http://localhost:8080/assets
```

Run the docs site:

```bash
cd ../docs
npm install
npm run dev               # http://localhost:3000
```
