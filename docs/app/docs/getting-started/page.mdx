# Getting Started

<LastReviewed date={metadata.lastReviewed} />

The **Stellar RWA Toolkit** is an end-to-end system for tokenizing real-world
assets (RWAs) — real estate, invoices, commodities — on Stellar using Soroban
smart contracts, with **compliance enforced on-chain**.

It has three parts, each in its own repository:

- **Contracts** — four Soroban contracts: `asset-token`, `compliance`, `registry`, `dividend`.
- **API** — a Rust/Axum service that indexes all tokenized-asset activity and serves it over REST.
- **Web app** — a Next.js front-end for issuers and investors.

<CalloutBox variant="warning" title="Project maturity">
The toolkit is early-stage (v0.1.0) and **deployed on Stellar Testnet only** —
there is no mainnet deployment. The contracts and API have **not been externally
audited**. Build and experiment against Testnet, but do not use this code to
custody real value until it has been independently audited and reviewed for
securities compliance.
</CalloutBox>

## What "tokenizing a real-world asset" means

A real-world asset — say a $5,000,000 Manhattan loft — is represented on-chain as
a fungible token. Each token is a fractional claim on the underlying asset. Unlike
an ordinary token, an RWA token is **compliance-gated**: only addresses that have
passed KYC and sit on an allowlist may hold or receive it.

The gate is not a policy sitting in a database — it is enforced by the contract
itself. On every transfer, the asset-token contract makes a cross-contract call
into the compliance contract to check both the sender and the recipient. If either
fails, the transfer reverts.

<CalloutBox variant="compliance" title="Why this matters">
Securities laws in most jurisdictions restrict who may hold a regulated asset.
Enforcing that restriction **in the contract** — rather than in an app that can be
bypassed — is what makes a token suitable to represent a regulated real-world
asset. See the [Compliance Guide](/docs/compliance-guide).
</CalloutBox>

<CalloutBox variant="tip" title="New to Stellar or Soroban?">
Unfamiliar terms are defined in the [Glossary](/docs/glossary). If something goes
wrong, start with [Troubleshooting](/docs/troubleshooting).
</CalloutBox>

## How the pieces fit together

```
                         ┌───────────────┐
   issuer / investor ──▶ │  Web app      │ ──▶ Freighter ──▶ Soroban contracts
                         └───────────────┘                       │
                                                                 │ events + state
                         ┌───────────────┐   polls Soroban RPC   │
   analysts / bots  ──▶  │  REST API     │ ◀─────────────────────┘
                         └───────────────┘
```

- The **web app** signs and submits transactions through the user's wallet.
- The **API** only reads: it indexes on-chain state every 10 seconds via
  `simulateTransaction` (the Soroban RPC method that runs a contract function
  read-only without submitting anything to the network) and never
  holds a key or signs anything.

## Prerequisites

- [Freighter](https://freighter.app) browser extension (for the web app)
- Node.js 18+ (web app and docs)
- Rust 1.75+ (API and contracts)
- The [Stellar CLI](https://developers.stellar.org/docs/tools/cli) (to deploy contracts)

## Quickstart

The fastest way to see the API working is to run it locally against the deployed
Testnet contracts — no wallet, no signing, no tokens required.

### 1. Clone and start the API

```bash
git clone https://github.com/RWA-ToolKit/stellar-rwa-api-docs
cd stellar-rwa-api-docs/api
cp .env.example .env      # Testnet contract IDs and RPC URL are pre-filled
cargo run
# → listening on 0.0.0.0:8080
```

The API is ready when you see `listening on 0.0.0.0:8080` in the terminal.
It will start polling Soroban Testnet immediately; the first snapshot is
available within ~10 seconds.

### 2. Hit the live endpoints

Open a second terminal and run these commands against `http://localhost:8080`.
Data endpoints use the `/v1` prefix; the liveness probe is `/health`.



returns `304 Not Modified` with no body, so reuse your cached response:

```bash
# Capture the ETag from the first response
curl -i http://localhost:8080/v1/assets/1
# ETag: "ledger-3514152"
# Cache-Control: public, max-age=10

# Send the ETag on a later request (use the value your response returned)
curl -i -H 'If-None-Match: "ledger-3514152"' http://localhost:8080/v1/assets/1
# HTTP/1.1 304 Not Modified
```

parameters. `offset` is the number of records to skip (starting at 0); `limit`
defaults to 50 and is capped at 100:

```bash

curl 'http://localhost:8080/v1/assets?offset=0&limit=20'
curl 'http://localhost:8080/v1/assets?offset=20&limit=20'

curl 'http://localhost:8080/v1/assets/1/holders?offset=0&limit=10'
curl 'http://localhost:8080/v1/assets/1/holders?offset=10&limit=10'
```

## Contract entry points

The contracts expose more than the basic mint/transfer surface. The table below
lists the entry points added after this page was first written, so you can find
them in the contract source and the API.

### Asset token (`asset-token`)

- **SEP-41 token interface** — the asset token implements the SEP-41 fungible
token standard (`allowance`, `approve`, `balance`, `transfer`, `transfer_from`,
`burn`, `burn_from`, `decimals`, `name`, `symbol`), so wallets and DEXes that
speak SEP-41 can interact with it directly.
- **Batch operations** — `batch_transfer` and `batch_mint` accept a list of
`(from, to, amount)` / `(to, amount)` entries and apply them in a single
transaction, reverting the whole batch if any entry fails compliance.
- **Admin handover** — `propose_admin` / `accept_admin` implement a two-step
transfer of the contract admin role; the new admin must accept before the
change takes effect.
- **Minimum holding period** — `set_min_holding_period` configures a lock-up
window; transfers that would move tokens before the period elapses revert.

### Dividend (`dividend`)

- **Dividend deadline** — `set_claim_deadline` sets the ledger after which
claims are no longer accepted.
- **Reclaim** — `reclaim_unclaimed` lets the issuer recover funds for
unclaimed dividends once the deadline has passed.
- **Cancel** — `cancel_distribution` cancels a distribution before it is
finalized, refunding the issuer.

### Pagination

List endpoints on the API (`/v1/assets`, `/v1/assets/{id}/holders`) accept
`offset` and `limit` as shown above. The contract-side list getters
(`get_holders`, `get_distributions`) accept the same `start` / `limit` window so
large sets can be read without exceeding the Soroban read-entry budget.

<CalloutBox variant="tip" title="Verify against the source">
The contract source is the source of truth for exact signatures. When in doubt,
read the `#[contractimpl]` block in the relevant contract before relying on an
entry point.
</CalloutBox>
