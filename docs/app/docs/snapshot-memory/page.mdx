# Snapshot Memory

<LastReviewed date={metadata.lastReviewed} />

The indexer keeps a full snapshot (assets, holders, compliance, dividends,
stats) in memory and rebuilds it every poll. Request handlers currently take a
full `Snapshot::clone()` per request.

## Measurement

Each refresh records:

- `rwa_indexer_snapshot_estimated_bytes` - approximate payload size (JSON
  length of every collection). Plot it against `rwa_indexer_snapshot_assets`
  to get bytes per asset; growth is linear in assets and in holders per asset.
- `rwa_indexer_snapshot_clone_duration_seconds` - time of one full clone,
  which is the extra per-request cost of the current design.

## Strategy

1. Serve requests from a shared `Arc<Snapshot>` (the `ArcSwap` guard already
   provides one), so a request costs a pointer copy instead of a deep clone.
2. Cap per-asset holder lists in the snapshot and page the remainder on demand
   once `rwa_indexer_snapshot_estimated_bytes` approaches the container limit.
3. Alert on `rwa_indexer_snapshot_estimated_bytes` growth per asset before
   changing storage (a database is the step after paging).
